## 任务 1: worktrees 目录匹配

### 问题描述
当用户使用 `--project polydev` 搜索时，只搜索 `E--Heyang3-polydev` 一个目录，忽略了相关的 worktree 目录：
- `E--Heyang3-polydev--worktrees-test-final`
- `E--Heyang3-polydev--worktrees-test-timing`
- `E--Heyang3-polydev--worktrees-test-timing2`
- 等等

### 解决方案
修改 `retrace-search.py` 的 `get_default_db_path()` 函数，当匹配到项目时，同时收集该项目的所有 worktree 子目录的数据库，合并搜索结果。

### 涉及文件
- `scripts/retrace-search.py`

### 修改要点
1. 将 `get_default_db_path()` 改为 `get_project_db_paths()` 返回列表
2. 匹配逻辑：`project.lower() in pd.name.lower()` 改为同时匹配 `{project}` 和 `{project}--worktrees-*`
3. 搜索时遍历所有匹配的数据库，合并结果
4. 结果按时间排序，标注来源项目

## 任务 2: chronicle 输出改造

### 问题描述
当前 `retrace-chronicle.py` 输出到 stdout，大量数据会爆 token 预算。

### 解决方案
- 必须指定 `--output FILE` 参数，结果写入文件
- stdout 只输出进度信息：块数、每块耗时、完成状态、总耗时

### 涉及文件
- `scripts/retrace-chronicle.py`

### 修改要点
1. 添加 `--output` 参数（必选）
2. 移除直接 `print(format_toon(events))` 到 stdout
3. 结果写入指定文件
4. stdout 输出格式示例：
   ```
   [1/5] 处理块 1... 完成 (3.2s)
   [2/5] 处理块 2... 完成 (2.8s)
   [3/5] 处理块 3... 完成 (4.1s)
   [4/5] 处理块 4... 完成 (3.5s)
   [5/5] 处理块 5... 完成 (2.9s)

   总计: 5 块, 1,234 事件, 耗时 16.5s
   输出文件: /path/to/output.toon
   ```

## 任务 4: 新增 list-session.py

### 问题描述
Agent 无法知道当前工程有哪些会话，需要用户自己选择。

### 解决方案
新增 `list-session.py` 脚本，列出当前工程的所有会话供用户选择。

### 涉及文件
- `scripts/list-session.py`（新建）

### 输出格式
```
当前工程: E:\Heyang3\polydev
匹配目录: E--Heyang3-polydev (+ 5 worktrees)

会话列表:
[1] abc12345... | 2026-01-07 14:30 | 42 条消息 | 实现用户认证功能
[2] def45678... | 2026-01-06 10:15 | 28 条消息 | 修复登录bug
[3] ghi78901... | 2026-01-05 16:00 | 156 条消息 | 重构API接口
[4] jkl01234... | 2026-01-04 09:30 | 63 条消息 | 添加单元测试
...

共 12 个会话
```

### 参数设计
```bash
# 列出当前工程的会话
python list-session.py

# 指定工程
python list-session.py --project polydev

# JSON 格式输出（供其他脚本调用）
python list-session.py --json
```

### 功能要点
1. 自动检测当前工作目录对应的项目
2. 包含 worktrees 子目录的会话
3. 从索引数据库读取摘要（如果有）
4. 按修改时间倒序排列
5. 显示会话 ID（前8位）、时间、消息数、摘要
